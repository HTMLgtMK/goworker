# 任务 1：/compact、/new 固化期间的前端进度条（实现）

核心思路：**不改 plugin.Command / engine**。statusbar 生命周期改为事件驱动——frontend 的 Eval 包装器在命令前后发 `phase` 事件，命令内部（compact 的固化/压缩阶段、new 的固化）用 `cb.Publish` 发阶段文本事件，ProgressAddon 订阅事件并驱动 Bar 的 Start/Stop 与标签显示。spinner + 阶段文本 + 耗时（LLM 进度无法算百分比）。

## 改动清单

### 1. 阶段事件定义（`ai-runtime/config`，与 EventIteration 同处）
新增 `EventPhase = "phase"`，payload 为 `PhaseEvent{Kind (begin/stage/end), Label string}`。

### 2. ProgressAddon 扩展（`daemon/internal/frontend/stdin/addon_progress.go`）
- 实现 `statusbar.Registerer`，在 `OnRegister` 订阅 `EventPhase`：
  - `begin`：若 bar 未激活则 `b.Start()`（Reset 自身：spinner/计时归零），设置 label；
  - `stage`：仅更新 label；
  - `end`：若已激活则 `b.Stop()`（定格 ✓ + 耗时为永久行）。
  - addon 用自身 `started` 标记防重入；所有事件都从主 goroutine 发布（命令在主 goroutine 执行），无并发问题。
- `Render()` 变为 `⠋ <阶段> ⏱ 12.3s`，label 空时维持现有形态。

### 3. Eval 包装器统一发 begin/end（`daemon/internal/frontend/stdin/stdin.go`）
- `runWithCancel` 改为：Eval 前 publish `PhaseEvent{Begin}`，`defer` publish `{End}`；删除现有的 `sb.Start()` / `sb.Stop()` / `go sb.Run(...)`。
- `Run()` 启动时开一条**常驻** `go f.sb.Run(appCtx, pauseFn)`（pauseFn 沿用 HITL 判断）；Bar.Run 在 `!active` 时空转，开销可忽略。
- 非 agent 斜杠命令也走 `runWithCancel`（即 `isAgent` 分支判断删除）——附带收益：同步阻塞的 /new 固化期间 Esc 可取消（ctx 沿 `ctx.Ctx` 传播进 checkpoint/LLM 调用）。
- `Bar.Stop()` 增加"从未 Tick 则静默"保护（Bar 内记 `ticked` 标记），避免 /help 这类瞬时命令也落一行 `✓ ⏱ 3ms`。

### 4. Session.Compact 发阶段事件（`ai-runtime/agent/session.go:236,297`）
`compactMemory` / `compactStore`：固化前 `cb.Publish(EventPhase, {Stage, "固化记忆中"})`、压缩前 `{Stage, "压缩会话历史中"}`；`cb.Publish` 判空保护。

### 5. /new 改同步固化（`daemon/internal/agent/commands.go:45-88`、`ai-runtime/agent/checkpoint.go`、`agent/plugin.go`）
- `Session` 新增 `CheckpointSync(ctx, conv, cb RunCallbacks)`：publish `{Stage, "固化旧会话记忆"}` → 走现有 `checkpoint()`（主 goroutine，可直接读 `s.deps.Config`）→ `cb.Write` 回显 `RenderCheckpointNotice` 结果（复用 CheckpointAsync 的文案与"无新内容也要回信号"逻辑）。
- `handleNew`：快照 → Archive → `startSession()` → 同步 `CheckpointSync`。
- 删除 `bgWg`（plugin.go:53-56,186）与 `CheckpointAsync`（checkpoint.go:50-70，仅 /new 在用）；同步固化失败（含取消）按现有警告文案回显"历史仅存 STM"。

### 6. 测试与验收
- ProgressAddon：begin/stage/end 序列、begin 时 Start 重置计时、end 定格、未 begin 收 end 不落行——表驱动单测。
- `CheckpointSync`：memory nil / 空 conv / 正常 / 取消，断言 publish 序列与输出。
- grep 确认 `CheckpointAsync`/`bgWg` 无残留引用；全量 `go build ./... && go test ./...`。
- 手动验收：`/compact` 期间状态栏 spinner + "固化记忆中"→"压缩会话历史中" 切换、Esc 可取消；`/new` 阻塞至固化完成、完成后定格 ✓ 并打印固化结果；`/help` 等瞬时命令无残留行。

# 任务 2：命令 autocomplete 设计文档（只出文档，不实现）

新增 `specs/002-command-autocomplete/design.md`（沿用 specs 编号目录约定）：

1. **交互形态**（已定）：Tab 按需补全，zsh/fish 风格。输入以 `/` 开头且光标在第一个词内时按 Tab：展示前缀匹配候选（命令名 + 描述，别名归并去重）；唯一候选直接补全；多候选进入 cycle，再按 Tab 轮换，Shift-Tab（CSI `ESC [ Z`）反向。
2. **数据源**：`engine.Commands()`（Name/Aliases/Description），frontend 启动时缓存排序；前缀过滤，`/` 后为空列出全部。
3. **键盘管线**：`key.go` 新增 `KeyTab`（0x09，当前落在 `b >= 0x20` 之外被静默丢弃）与 `KeyShiftTab`；`editor.Consume` 增加分支；Esc 仍放行 keyWatcher，弹层随行取消自然消失。
4. **渲染**：候选列表渲染在输入行下方，复用 `redrawInput` 的多行擦除机制（`renderedRows` 已支持多行）；描述灰色弱化（同 thinking 色）；与底部 statusbar 清栏重绘互不干扰。
5. **Phase 2：参数补全**：`plugin.Command` 增加可选 `Completer` 接口（`Complete(args []string) []string`），engine 提供 `Complete(name, args)`；第一个词已完整时 Tab 触发参数补全（如 `/model use` → providers）。
6. **Phase 3（可选）**：历史持久化、Ctrl+R 模糊搜索、候选超终端行数时截断 + 计数提示。
7. **测试**：decoder Tab/Shift-Tab 解码单测、前缀过滤与别名归并表驱动测试。
